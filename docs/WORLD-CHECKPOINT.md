# World checkpoint

`SimulationWorldCheckpoint` is the composite canonical JSON boundary for the currently integrated Python simulation pipeline. It captures the authoritative event journal, NPC state and memories, trust interactions, observer-specific belief/evidence history, memory-adapter replay keys, conversation replay signatures/results, tick-coordinator replay history, and—when supplied—the separate witnessed-social-consequence recorder's replay inputs/results, optionally the campaign-level one-life lifecycle and archived world timelines, and optionally misconduct reports with their complete review history, and optionally planned NPC routine schedules, testimony inquiries, materialized witness testimony, and explicit NPC identity decisions, associative psychological conditioning, and accepted/rejected psychological learning decisions.

## Capture and restore

Use `SimulationWorldCheckpoint.capture(current_tick, coordinator, npcs, metadata=..., consequence_recorder=..., campaign=..., misconduct=..., routines=...)` to capture a consistent set of components. The optional `campaign` is a `LifeItselfCampaign`; its active life, death/spectator/ghost state, persistent world values, and archived timelines are included as a separate versioned section. The optional `consequence_recorder` must share the coordinator's trust ledger and belief system. The optional `misconduct` value is a `MisconductReportingSystem`; every incident reference must resolve to an event in the checkpoint's authoritative event ledger. Reports and decision histories are emitted under the optional `misconduct` section. The optional `routines` value is a `RoutineBook`; planned routine blocks are saved under the optional `routines` section. The optional `testimony_inquiries` value is a `TestimonyInquiryLedger`; inquiry and response history is saved under `testimony_inquiries` after validating event/witness references and checkpoint-time bounds. The optional `testimony` value is a `TestimonyLedger`; materialized accounts are saved under `testimony` after validating source event, event tick, witness identity, and checkpoint-time bounds. The optional `identity_decisions` value is an `IdentityDecisionLedger`; accepted and rejected identity changes are saved with initial/current profiles, and capture verifies that every profile belongs to an NPC in the checkpoint roster and that each decision matches its source event, role, and time. The optional `conditioning` value is an `NPCConditioningLedger`; the optional `psychological_learning_decisions` value is a `PsychologicalLearningDecisionLedger` and requires the matching conditioning ledger. Accepted learning decisions must have their exact `psych-learning:<decision_id>` conditioning record; rejected decisions must not have one. Both components are checked against the NPC roster, authoritative source event, and checkpoint tick. The resulting JSON is deterministic and sorted; the `consequence_replay` section is emitted only when a recorder was included.

Restore creates the event ledger, NPCs, trust, beliefs, memory adapter and replay index, conversation adapter and replay index, tick coordinator and replay history, then the optional consequence recorder and its replay index, then the optional misconduct reporting system after validating its incident references against the restored event ledger, then the optional routine schedule book, inquiry ledger, testimony ledger, identity decision ledger, conditioning ledger, and psychological learning decision ledger. Learning-decision restore validates source-event participation/witness status and confirms that accepted decisions have exactly their corresponding conditioning records while rejected decisions remain unapplied. Identity restore validates the decision history against stored initial traits, reconstructs accepted changes exactly once, and retains rejected decisions without changing traits. When present, the campaign is restored as a separate timeline manager; character death does not delete the event journal or NPC state captured by the simulation checkpoint. Existing trust and belief histories are restored before consequence replay records, so replaying a previously recorded witnessed event returns its original result rather than applying its trust/evidence effects twice.

## Scope and limitations

This is a persistence boundary for the currently connected Python reference systems, not yet a complete game save format. Capture does not provide a cross-component single-lock atomic snapshot; callers should pause mutation while capturing. The coordinator does not automatically invoke the separate `WorldEventSocialAdapter` or `SocialConsequenceRecorder`; callers still explicitly record witnessed interpretations and pass the recorder to capture. Unreal presentation, engine state, routine schedule definitions can now be included, but generated disruptions and resolved attendance are not yet persisted and routine execution is not yet connected to world ticks. All other future simulation systems remain outside this checkpoint until explicitly integrated. Misconduct evidence IDs remain references; this codec does not fabricate or persist a separate evidence registry. The campaign section currently stores the existing `LifeItselfCampaign` reference model; it does not automatically advance campaign days when the simulation tick coordinator advances. A checkpoint round trip and replay tests exist in `tests/test_world_checkpoint.py`; the inquiry/testimony integration also replays the same answered inquiry after restore and checks that testimony and observer belief evidence are not duplicated. These tests must be run in the repository environment before claiming a verified pass.
