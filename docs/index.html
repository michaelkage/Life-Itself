02 / CONTRACTS

How decisions are made

Goal selection is not action planning

GoalBook ranks an NPC's actionable goals. The documented score is priority × (0.5 + 0.5 × confidence) × urgency × (1 − 0.25 × progress). Dependencies must be completed. A deadline raises urgency up to a 2× multiplier. Equal scores use stable goal-ID ordering.

Planning uses declared facts

DeterministicPlanner searches a finite symbolic state space with positive integer action costs, preconditions, add/delete effects, a least-cost priority queue and stable action-ID tie-breaking. Search is bounded by max_expansions. It does not infer facts or execute actions; the caller must revalidate each action against the live world.

Beliefs belong to observers

BeliefLedger replays evidence in (observed_tick, evidence_id) order. Each evidence item's influence is strength × source_reliability, moving confidence toward 1 for support or 0 for contradiction. SocialBeliefSystem uses the listener's trust in the source at observation time. Later trust changes do not rewrite earlier evidence.

Reproducibility is explicit

These systems do not read wall-clock time or a hidden global random generator. Where uncertainty is required, callers provide tick values, samples, evidence, or seeded streams. Stable ordering and replay signatures make the same supplied history reproducible; a different history can produce a different outcome.

03 / CONSTRAINTS

What is not finished

AreaCurrent engineering state
Unreal EnginePresentation, animation, physics and asset integration are not implemented.
Python goals/planningEngine-independent reference implementation; C++ parity and full world/campaign integration remain future work.
Routine executionPython reference and persistence/adapters exist. The world driver must explicitly call the routine phase and provide inputs.
GPU computeWGSL kernels, packed contracts and CPU references exist. No production WebGPU/Vulkan device adapter or GPU runtime is connected.
Physical worldPortable C++ core models selected simulation domains; it is not a rendered, spatially complete open world.
External dependenciesPython reference suite uses the standard library. C++ build requires CMake 3.20+ and a C++20 compiler.

Do not infer: a routine resolution does not prove physical arrival; a plan does not execute itself; a rumor is not objective truth; a CPU reference is not a live GPU backend.

04 / BUILD & TEST

Run the reference core

Python 3.10+ is required for the reference package. The README's standard-library test command is:

python -m unittest discover -s tests -t .

The portable C++ core requires C++20 and CMake 3.20+:

cmake -S cpp -B build
cmake --build build
ctest --test-dir build --output-on-failure

Python reference regression cases for the mechanisms shown here include tests/test_routines.py, tests/test_planning.py, tests/test_npc_autonomy.py, and checkpoint tests. CI runs the Python suite with pytest on Python 3.11.
